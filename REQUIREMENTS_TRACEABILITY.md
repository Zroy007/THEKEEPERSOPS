# Requirements Traceability Matrix

This document provides a systematic verification of every original architectural and functional requirement against the concrete implementation in the codebase.

---

| Requirement | Expected Behavior | Current Implementation | Status | Relevant Files | Notes |
|---|---|---|---|---|---|
| **Firestore as Canonical Runtime State** | Cloud Firestore should persist all platform entities (jobs, sessions, tasks, attempts, settings). | The system contains complete `firestore.rules`, `firestore.indexes.json`, and `firebase-blueprint.json` schemas, but the current runtime repository persists atomically to `data/platform_db.json`. | **PARTIAL** | `firestore.rules`, `firebase-blueprint.json`, `server/db/repository.ts` | Firestore configuration is authored and deployment-ready; runtime uses local atomic file persistence for container independence. |
| **Google Sheets as Operator/Reporting Layer** | Bi-directional synchronization for queue intake and performance reporting. | Mock sync handles bidirectional pull/push with idempotency; CSV export is fully implemented; direct Google Sheets v4 API call is stubbed. | **PARTIAL** | `server/services/googleSheets.service.ts`, `src/pages/SheetsSyncPage.tsx` | Mock path validates queue limits and idempotency; live REST calls to Google Sheets require completing the service account JWT flow. |
| **Dynamic Session Capacity** | System dynamically calculates available execution slots based on running sessions without hardcoded bounds. | Worker calculates `availableSlots = settings.concurrencyLimit - runningSessions.length` at runtime. | **IMPLEMENTED** | `server/routes.ts` (lines 692–704), `tests/queueEngine.test.ts` | Tested and verified in unit tests; slot allocation dynamically scales with active sessions. |
| **NO Hardcoded 6-Session Limitation** | Concurrency must not be locked to 6 sessions. | Concurrency limit is fully configurable via `settings.concurrencyLimit` (defaults to 12, adjustable from 1 to 50 via UI slider). | **IMPLEMENTED** | `server/types.ts`, `server/db/seed.ts`, `src/pages/SystemSettingsPage.tsx` | Verified: limit is dynamically loaded from `SystemSettings` object. |

| **Configurable Concurrency** | Administrators can adjust concurrent browser execution limits. | Settings API (`PATCH /api/admin/settings`) supports live modification of `concurrencyLimit`. | **IMPLEMENTED** | `server/routes.ts`, `server/adminRoutes.ts`, `src/pages/SystemSettingsPage.tsx` | UI slider with numeric input and instant validation. |
| **Configurable Daily Job Limit** | Administrators can adjust maximum allowable jobs per 24-hour cycle. | Stored in `settings.dailyJobLimit`; checked before new job creation and queue dispatch. | **IMPLEMENTED** | `server/validators/schemas.ts`, `src/pages/SystemSettingsPage.tsx` | Supported in validation schemas and UI. |
